# Installation & Deployment Guide

This guide walks you through deploying **wisper** in production or staging with a distributed topology: the **Panel** running on one host and one or more **Nodes** running on independent remote hosts.

---

## Architecture Overview

- **Panel (`wisper`)**: Single executable Spring Boot jar (`wisper-<version>.jar`) containing the backend API, scheduler, and React frontend. Communicates with PostgreSQL 17.
- **Node Daemon (`sasayaki`)**: Single static Go binary (`sasayaki-linux-<arch>`) with embedded Caddy edge proxy, talking to the local Docker engine.
- **Node dials out**: Nodes always initiate and maintain an outbound gRPC control stream to the panel (`:9090`). The panel never dials nodes.
- **Download CDN**: By default, `/install.sh` generated by the panel downloads daemon binaries directly from the official **GitHub Releases CDN (`releases/latest/download`)**, avoiding bandwidth exhaustion and DoS risks on the panel server.

---

## 1. Setting Up the Panel (`wisper`)

### 1.1 Install Prerequisites (Java 21 & PostgreSQL)

Run the package installation command for your distribution:

**Ubuntu 24.04 / Debian 12 / Ubuntu 22.04:**
```bash
sudo apt update
# Install OpenJDK 21 headless runtime and PostgreSQL
sudo apt install -y openjdk-21-jre-headless postgresql postgresql-contrib

# Verify Java is installed at /usr/bin/java
java -version
```

*(Optional: For RHEL / Rocky / AlmaLinux 9)*:
```bash
sudo dnf install -y java-21-openjdk-headless postgresql-server postgresql-contrib
sudo postgresql-setup --initdb && sudo systemctl enable --now postgresql
```

### 1.2 Prepare Database
Create the database and database user:
```bash
sudo -u postgres psql -c "CREATE USER wisper WITH PASSWORD 'your_db_password';"
sudo -u postgres psql -c "CREATE DATABASE wisper OWNER wisper;"
```

### 1.3 Download the Latest Panel Release
Download the latest `wisper.jar` from GitHub Releases:
```bash
sudo mkdir -p /opt/wisper /etc/wisper
cd /opt/wisper

# Fetch latest panel jar
curl -fsSL -o wisper.jar https://github.com/furimeo/wisper/releases/latest/download/wisper-0.1.8.jar
```

### 1.4 Generate Encryption Key & Environment
The panel uses AES-256-GCM to reversibly encrypt customer credentials and secrets.

Run the following command directly in your terminal (bash/sh) to automatically generate a cryptographically random 32-byte key and initialize `/etc/wisper/panel.env`:

```bash
# Run this entire block directly in your terminal:
sudo bash -c "cat <<EOF > /etc/wisper/panel.env
WISPER_DB_USER=wisper
WISPER_DB_PASSWORD=your_db_password
WISPER_CRYPTO_KEY_1=$(openssl rand -base64 32)

# Optional: Override daemon download base (defaults to GitHub Releases latest CDN)
# WISPER_NODE_UPGRADE_DOWNLOAD_BASE=https://github.com/furimeo/wisper/releases/latest/download
EOF"
```

> **Note**: Do not copy the block above into a text editor (like `nano`) manually, because `$(openssl rand -base64 32)` needs to be evaluated by your shell.
>
> If you need to edit your database password or configuration later, edit the generated file:
> ```bash
> sudo nano /etc/wisper/panel.env
> ```
>
> **Important**: Never commit or hardcode `WISPER_CRYPTO_KEY_1`. Back up this key securely; if lost, encrypted database secrets cannot be decrypted.

### 1.5 Configure Systemd Service
Create `/etc/systemd/system/wisper-panel.service`:
```ini
[Unit]
Description=wisper hosting panel
After=network.target postgresql.service
Wants=postgresql.service

[Service]
Type=simple
User=wisper
Group=wisper
WorkingDirectory=/opt/wisper
EnvironmentFile=/etc/wisper/panel.env
ExecStart=/usr/bin/java -jar /opt/wisper/wisper.jar
Restart=always
RestartSec=5s
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

Enable and start the service:
```bash
sudo id -u wisper &>/dev/null || sudo useradd -r -s /bin/false -d /opt/wisper wisper
sudo chown -R wisper:wisper /opt/wisper /etc/wisper
sudo chmod 600 /etc/wisper/panel.env

sudo systemctl daemon-reload
sudo systemctl enable --now wisper-panel
```

Inspect the logs:
```bash
sudo journalctl -u wisper-panel -f
```
On first boot with an empty database, the panel runs migrations automatically, creates the initial administrator user, and prints a temporary password in a `WARN` log line. Save this password, navigate to your panel domain (e.g. `https://panel.example.com`), sign in, and update your credentials.

## 2. Setting Up a Remote Node (`sasayaki`)

On each server you want to run customer workloads:

### 2.1 Prerequisites
- **OS**: Linux (`x86_64` / `amd64` or `aarch64` / `arm64`).
- **Docker Engine**: Installed and running (`systemctl status docker`).
- **gVisor `runsc`** (Recommended for sandboxed tenant isolation):
  ```bash
  # Optional but recommended for workload isolation
  sudo apt-get install -y runsc
  ```

### 2.2 Generate Node Token
1. Go to **Admin ➔ Nodes** (`/admin/nodes`) on the panel web interface.
2. Click **Create Node**, input a node name (e.g. `node-01`).
3. Click **Generate Enrollment Token**. The panel generates a single-use token valid for 15 minutes and displays the custom install command.
4. Save the token into a file on the target node:
   ```bash
   echo "YOUR_ENROLLMENT_TOKEN" > token.txt
   ```

### 2.3 Run the Installer
Run the install command generated by the panel (using your panel domain):
```bash
curl -fsSL https://<your-panel-domain>/install.sh -o install.sh
chmod +x install.sh
sudo ./install.sh --token-file token.txt
```

#### Why use the panel-served `install.sh`?
- **Automatic Configuration**: The panel automatically bakes in your panel domain URL, gRPC dial endpoint, and the exact SHA-256 checksums of the published node binary for your machine architecture.
- **Security & DoS Protection**: While the script is dynamically served by the panel, the heavy binary payload is downloaded directly from the **GitHub Releases CDN**.
- **Preflight & Verification**: Runs `sasayaki doctor` checks (Docker socket, cgroups v2, routing), performs gRPC handshake with the panel on port 9090, pins the certificate, stores credentials in `/etc/wisper/node.json`, deletes `token.txt`, and starts `sasayaki.service`.

### 2.4 Offline / Air-gapped Node Installation
If the node cannot reach GitHub Releases or the panel directly over HTTP:
1. Download from the [GitHub Releases](https://github.com/furimeo/wisper/releases/latest):
   - `install.sh`
   - `sasayaki-linux-amd64` (or `sasayaki-linux-arm64`)
   - `SHA256SUMS`
2. Copy them to the node in the same directory:
   ```bash
   chmod +x install.sh
   sudo ./install.sh --token-file token.txt --panel <panel-grpc-endpoint>
   ```
The installer automatically picks up the local binary and verifies its checksum against `SHA256SUMS`.

## 3. Firewall & Ports Summary

| Component | Port | Protocol | Direction | Description |
|---|---|---|---|---|
| **Panel** | `80` & `443` (or reverse proxy) | HTTP/HTTPS | Inbound | Web panel for administrators & users |
| **Panel** | `9090` | gRPC (HTTP/2) | Inbound | Control stream dialed by nodes |
| **Node** | `80` & `443` | HTTP/HTTPS | Inbound | Public traffic for customer apps & sites (served by embedded Caddy) |
| **Node** | Any | Outbound | Outbound | Dials Panel `:9090` and pulls Docker images |

> **Note**: Nodes never listen on port 9090 and require zero inbound ports for cluster management. The panel web interface can be safely hidden behind a private network, VPN, or Cloudflare Tunnel, as long as nodes can reach the gRPC endpoint.
