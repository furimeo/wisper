# Installation & Deployment Guide

This guide walks you through deploying **wisper** in production or staging with a distributed topology: the **Panel** running on one host and one or more **Nodes** running on independent remote hosts.

---

## Architecture Overview

- **Panel (wisper)**: Single executable Spring Boot jar (wisper-<version>.jar) containing the backend API, scheduler, and React frontend. Communicates with PostgreSQL 17.
- **Node Daemon (sasayaki)**: Single static Go binary (sasayaki-linux-<arch>) with embedded Caddy edge proxy, talking to the local Docker engine.
- **Node dials out**: Nodes always initiate and maintain an outbound gRPC control stream to the panel (:9090). The panel never dials nodes.
- **Download CDN**: By default, /install.sh generated by the panel downloads daemon binaries directly from the official **GitHub Releases CDN (eleases/latest/download)**, avoiding bandwidth exhaustion and DoS risks on the panel server.

## 1. Setting Up the Panel (wisper)

### 1.1 Prerequisites
- **OS**: Linux (Ubuntu 22.04/24.04, Debian 12, etc.) or any OS with Java 21 LTS.
- **Java Runtime**: OpenJDK 21 LTS (pt install openjdk-21-jre-headless).
- **Database**: PostgreSQL 17 (or 15+).

### 1.2 Prepare Database
Create the database and database user:
`ash
sudo -u postgres psql -c "CREATE USER wisper WITH PASSWORD 'your_db_password';"
sudo -u postgres psql -c "CREATE DATABASE wisper OWNER wisper;"
`

### 1.3 Download the Latest Panel Release
Download the latest wisper-*.jar from GitHub Releases:
`ash
sudo mkdir -p /opt/wisper
cd /opt/wisper

# Fetch latest jar
curl -fsSL https://github.com/furimeo/wisper/releases/latest/download/wisper-0.1.7.jar -o wisper.jar
`

### 1.4 Generate Encryption Key & Environment
The panel uses AES-256-GCM to reversibly encrypt customer credentials and secrets. Generate a 32-byte Base64 key:
`ash
openssl rand -base64 32
# Example output: v8Xv7W1mK9vL0pZ2yA3bC4dE5fG6hI7jK8lM9nO0123=
`

Create /etc/wisper/panel.env:
`ini
WISPER_DB_USER=wisper
WISPER_DB_PASSWORD=your_db_password
WISPER_CRYPTO_KEY_1=v8Xv7W1mK9vL0pZ2yA3bC4dE5fG6hI7jK8lM9nO0123=

# Optional: Override daemon download base (defaults to GitHub Releases latest CDN)
# WISPER_NODE_UPGRADE_DOWNLOAD_BASE=https://github.com/furimeo/wisper/releases/latest/download
`

### 1.5 Configure Systemd Service
Create /etc/systemd/system/wisper-panel.service:
`ini
[Unit]
Description=wisper hosting panel
After=network.target postgresql.service
Wants=postgresql.service

[Service]
Type=simple
User=wisper
Group=wisper
WorkingDirectory=/opt/wisper
EnvironmentFile=/etc/wisper/panel.env
ExecStart=/usr/bin/java -jar /opt/wisper/wisper.jar
Restart=always
RestartSec=5s
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
`

Enable and start the service:
`ash
sudo id -u wisper &>/dev/null || sudo useradd -r -s /bin/false -d /opt/wisper wisper
sudo chown -R wisper:wisper /opt/wisper /etc/wisper
sudo chmod 600 /etc/wisper/panel.env

sudo systemctl daemon-reload
sudo systemctl enable --now wisper-panel
`

Inspect the logs:
`ash
sudo journalctl -u wisper-panel -f
`
On first boot with an empty database, the panel runs migrations automatically, creates the initial administrator user, and prints a temporary password in a WARN log line. Save this password, sign in via http://<panel-ip>:8080, and update your credentials.

## 2. Setting Up a Remote Node (sasayaki)

On each server you want to run customer workloads:

### 2.1 Prerequisites
- **OS**: Linux (x86_64 / amd64 or aarch64 / arm64).
- **Docker Engine**: Installed and running (systemctl status docker).
- **gVisor unsc** (Recommended for sandboxed tenant isolation):
  `ash
  # Optional but recommended for workload isolation
  sudo apt-get install -y runsc
  `

### 2.2 Generate Node Token
1. Go to **Admin ➔ Nodes** (/admin/nodes) on the panel web interface.
2. Click **Create Node**, input a node name (e.g. 
ode-01).
3. Click **Generate Enrollment Token**. The panel generates a single-use token valid for 15 minutes.
4. Save the token into a file on the target node:
   `ash
   echo "YOUR_ENROLLMENT_TOKEN" > token.txt
   `

### 2.3 Run the Installer
Run the install command generated by the panel:
`ash
curl -fsSL https://<your-panel-domain-or-ip>:8080/install.sh -o install.sh
chmod +x install.sh
sudo ./install.sh --token-file token.txt
`

#### What happens during installation:
1. Detects machine architecture (md64 or rm64).
2. Downloads sasayaki directly from the **GitHub Releases CDN** (or custom CDN/mirror if configured).
3. Verifies binary SHA-256 against the hash baked into the installer script.
4. Runs sasayaki doctor preflight checks (Docker socket, cgroups v2, network routing).
5. Performs gRPC handshake with the panel on port 9090, pins the certificate, and stores credentials in /etc/wisper/node.json.
6. Deletes 	oken.txt and starts sasayaki.service.

### 2.4 Offline / Air-gapped Node Installation
If the node cannot reach GitHub Releases or the panel directly over HTTP:
1. Download from the [GitHub Releases](https://github.com/furimeo/wisper/releases/latest):
   - install.sh
   - sasayaki-linux-amd64 (or sasayaki-linux-arm64)
   - SHA256SUMS
2. Copy them to the node in the same directory:
   `ash
   chmod +x install.sh
   sudo ./install.sh --token-file token.txt --panel <panel-host>:9090
   `
The installer automatically picks up the local binary and verifies its checksum against SHA256SUMS.

## 3. Firewall & Ports Summary

| Component | Port | Protocol | Direction | Description |
|---|---|---|---|---|
| **Panel** | 8080 (or 80/443) | HTTP/HTTPS | Inbound | Web panel for administrators & users |
| **Panel** | 9090 | gRPC (HTTP/2) | Inbound | Control stream dialed by nodes |
| **Node** | 80 & 443 | HTTP/HTTPS | Inbound | Public traffic for customer apps & sites |
| **Node** | Any | Outbound | Outbound | Calls Panel :9090 and pulls Docker images |

> **Note**: Nodes never listen on port 9090 and require zero inbound ports for cluster management. The panel can be safely hidden behind a VPN or Cloudflare Tunnel.
