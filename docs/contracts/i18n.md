# Translation

Binding. See [README.md](README.md).

wisper ships in English and Vietnamese, and *every* user-visible sentence is translated -
including the long explanatory ones. Those paragraphs are not decoration: they are where
this product explains consequences, and a warning about disk quota that only an English
reader can act on is a warning that does not work.

## Two catalogues, on purpose

| Written by | Lives in | Read by |
|---|---|---|
| The server | `panel/src/main/resources/wisper/messages/messages[_xx].properties` | `MessageSource`: flash messages, Bean Validation, error pages |
| The browser | `panel/frontend/src/i18n/<locale>/<feature>.json` | `t()` in React components |

They are separate because shipping the server's catalogue to the browser would send every
string in the product on every page load, most of them for screens the visitor will never
open. Nothing is duplicated between them: a sentence is written by exactly one side.

## The browser side

```tsx
import {t} from '@/i18n'

t('deploy.list.title')
t('deploy.list.empty', {project: project.name})
t('service.count', {count: services.length})
```

- **No hook, no provider.** The catalogue is loaded once before the first render and cannot
  change within the life of a page: the language is a property of the account, and changing
  it is a form post and a fresh render.
- **Keys are `feature.screen.thing`** and match the folder the string is used in. That is
  what lets somebody find a sentence they can see on screen - which is exactly what they
  cannot do by grepping for its English text once the screen is in Vietnamese.
- **A missing key renders as the key.** Ugly on purpose: visible in a screenshot, and
  greppable.
- **Plurals**: a catalogue entry may be `{one, other}` and the form is chosen from
  `params.count`. English splits at one; Vietnamese has no grammatical plural, so a
  Vietnamese entry is a plain string and the number in front of the noun carries the
  meaning. Do not write a pair in `vi/`.
- **Interpolation** is `{name}`, filled from the params object. A placeholder with no
  matching param is left visible rather than blanked.

### Where a string goes

`src/i18n/en/<feature>.json` and `src/i18n/vi/<feature>.json`, one pair per feature folder.
The locale's `index.ts` globs its folder, so **adding a feature's strings is dropping two files in** -
there is no index to register them in and therefore no index to forget.

Only strings that appear on more than one screen and belong to no feature go in
`shell.json`.

## The server side

`messages.properties` is English and the fallback for every other file, so a key missing
from `messages_vi.properties` renders in English rather than as a raw key. Keys are dotted
and named after the package that raises them.

The files are read as UTF-8. `.properties` defaults to ISO-8859-1, in which Vietnamese is
mojibake that loads without error.

## Which language a request gets

`PanelLocale`, in this order:

1. the signed-in account's `locale` column, which wins whenever there is one - otherwise
   somebody who chose Vietnamese sees English on a borrowed laptop;
2. `Accept-Language`, walked in the order the browser sent it, for the sign-in and error
   pages where there is no account yet;
3. English.

`SupportedLocale` is the one list of languages, and the `account_locale_supported` CHECK
enforces the same list in the database. **A language joins it only when both catalogues are
complete**: a half-translated language is worse than an untranslated one, because the
reader cannot tell a missing string from a deliberate English term.

## What is not translated

- Technical terms the operator community uses in English regardless: `node`, `backup`,
  `API token`, `runsc`, `cron`. Translating them makes the reader translate back to compare
  against their own tooling and against every other document they have.
- Identifiers, slugs, hostnames, log lines, and anything a machine reads.
- A language's own name in the picker. `Tiếng Việt` is written that way in the English UI
  too, because the person who needs that control is the one who cannot read the current
  language.
